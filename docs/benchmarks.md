# Benchmarks

Every model on this page is scored by `spindle bench` on the same cases and rules. None of these datasets appear in the training mix generated by `spindle build-data`.

### Reading the results

- **Sampling noise**: With 200 cases per set, standard error near 50% is about ±3 points, so small differences between models are within noise.
- **CPU vs. GPU timing**: Latency is the mean time per request including prompt processing. `llama.cpp` runs on the Apple silicon GPU with 4 threads, while Spindle (2 threads by default on this laptop) and Needle 3 run on the CPU only.
- **Plain-text replies**: Even with `tool_choice: required`, LFM3-1.7B generated free text up to the 512-token limit on most Rotten Tomatoes reviews (lowering its score to 15.5 and raising its average latency). Qwen3.5-0.8B also replied with plain text instead of tool calls on many Rotten Tomatoes (calling on 37%) and DroidCall (40%) cases.
- **Invalid enum values**: FunctionGemma-270M often copied text from the prompt (such as an article title for `topic`) or invented labels instead of selecting from the schema enum. Because `llama.cpp` does not parse its call syntax, a small adapter stops at `<end_function_call>` and extracts the call without altering the text.
- **Spindle defaults**: Output filters (`filters=True`) check calls against the prompt before returning them, which improves abstention at the cost of lower recall when disabled (see [what changed from Needle 3](changes-from-needle-3.md)). Enum debiasing is also on by default (`--no-debias-enums` drops DBpedia from 46.5 to 28.0 and mean to 47.9, with other sets within 1.5 points).
- **Charts and full logs**: Qwen and FunctionGemma are omitted from the three-model charts, but per-set summaries including call and decline rates for every model live in [`benchmarks/results/`](../benchmarks/results).

## Benchmarks and scoring

| Set | Task | What a case is | Metric |
| --- | --- | --- | --- |
| [Mobile Actions](https://huggingface.co/datasets/google/mobile-actions) | Tool calling | Phone-assistant request with tool list and date system prompt | Exact match of all calls and arguments |
| [DroidCall](https://huggingface.co/datasets/mllmTeam/DroidCall) | Tool calling | Android intent request | Exact match |
| [BFCL v4](https://github.com/ShishirPatil/gorilla/tree/main/berkeley-function-call-leaderboard) | Tool calling + declining | Single-turn subsets: simple, multiple, parallel, live, and live relevance/irrelevance | BFCL AST match (any order, listed alternatives accepted) |
| [When2Call](https://huggingface.co/datasets/nvidia/When2Call) | Declining | Request that either requires a tool call or should be declined | Decision accuracy (call vs. no call) |
| Tool removed | Declining | Single-call Mobile Actions case with the target tool removed from the list | Decision accuracy (no call) |
| [DSTC8](https://github.com/google-research-datasets/dstc8-schema-guided-dialogue) | Extraction | User turn from schema-guided dialogues using the service's intents as tools | F1 over `(tool, argument, value)` |
| [SNIPS](https://github.com/MiuLab/SlotGated-SLU) | Extraction | Voice-assistant request with only the matching intent provided as a tool | F1 over `(tool, argument, value)` |
| SNIPS 7-way | Extraction | Same requests with all seven intents provided as tools | F1 over `(tool, argument, value)` |
| [Rotten Tomatoes](https://huggingface.co/datasets/cornell-movie-review-data/rotten_tomatoes) | Classification | Movie review with a single tool containing a `sentiment` enum | Accuracy |
| [DBpedia](https://huggingface.co/datasets/fancyzhx/dbpedia_14) | Classification | Short encyclopedia entry with a single tool containing a 14-way `topic` enum | Accuracy |

String comparisons ignore case and extra whitespace, and `5` matches `5.0`. All other types must match exactly. Extraction and classification tasks require a tool call (`require_call`), so models cannot score by abstaining.

## Test setup

All runs used a single Apple M1 laptop (8 GB RAM), running one model at a time with greedy decoding on the same 200-case random sample per set (seed `0`).

| Model | File | Runtime | Settings |
| --- | --- | --- | --- |
| Spindle | `spindle.cact` (4-bit) | This repository's engine | Window 1024, output filters, copy guard, enum debiasing on |
| Needle 3 | Shipped `needle3.cact` (2-bit) | Official Cactus engine | Default settings |
| LFM3-1.7B | `LFM3-1.7B-Q4_K_M.gguf` | `llama-server` (`b11960`) | Chat template with tools, thinking off, 4 threads |
| Qwen3.5-0.8B | `Qwen3.5-0.8B-Q4_K_M.gguf` | `llama-server` (`b11960`) | Chat template with tools, `--chat-template-kwargs '{"enable_thinking":false}'`, 4 threads, 1 slot, prompt cache off |
| FunctionGemma-270M | `functiongemma-270m-it-Q4_K_M.gguf` | `llama-server` (`b11960`) + adapter | Chat template with tools, 4 threads, 1 slot, prompt cache off |

## Reproducing and scoring other models

Install the dataset dependencies and run `spindle bench` on a `.cact` file (about 30 minutes on an M1 with `--quick`):

```sh
pip install -e '.[data]'
spindle bench models/spindle.cact --quick --output report.json
```

Omit `--quick` to run the full datasets instead of 200 cases per set, or filter with `--sets` and `--limit`. The output JSON stores every prediction alongside the ground truth for error inspection.

You can score any OpenAI-compatible server the same way:

```sh
llama-server -m model.gguf --jinja --port 8080
spindle bench my-model --server http://127.0.0.1:8080/v1 --quick --output report.json
```

To regenerate the plots, place your report in `benchmarks/results/` with `name`, `size_mb`, and `order` fields added and run:

```sh
python benchmarks/plot.py
```
